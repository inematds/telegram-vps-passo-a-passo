In a nutshell

This step-by-step guide shows you how to build, on your own VPS, a Telegram bot that sends your requests to Claude Code through your subscription. It’s for anyone with a server who wants to manage it from their phone without handing the AI the keys to the house: only you can talk to the bot, the AI can only read, and every change waits for your “yes.” There are 9 steps, each with the command, the expected output, and a fake Telegram setup for testing. You need a Linux VPS with Python 3, Claude Code logged in through your subscription, and a Telegram account.

How it works

Five safeguards, all enforced in code

None of these safeguards depend on the AI “following instructions.” Each is a rule the program enforces, even if the AI makes a mistake or is tricked by a file.

You on Telegram→Owner list→AI can only read→Proposal checked→Your “yes”→Bot runs it and logs it
1

Entry with an allowlist

Only numbers on the list can get in. An empty list means nobody gets in; the bot only logs who tried.

2

Look around without changing anything

The AI can inspect files, but only inside a work folder, and it never sees keys, SSH, or logins.

3

Plan before taking action

To change anything, the AI only writes what it would do. The bot checks the proposal against a short list of allowed commands.

4

You give the final approval

Only a clear “yes” gives the go-ahead, and it’s valid for 10 minutes. The bot runs exactly what it showed you.

5

Audit log

Each request, proposal, “yes,” and result is recorded on a line in auditoria.jsonl, without the token.

⚠️ The security gap this guide closes

Claude Code combines the permissions in your own settings.json with the bot’s permissions. We tested it: on a machine where rm was allowed, the request “delete the logs folder” actually deleted it, even though the bot asked for “read only.” In step 5, the bot starts ignoring those settings (--setting-sources ""), and the final test deliberately plants that kind of trap to prove it doesn’t work.

Set up the VPS and Claude Code

Log in as a regular user (not root), install Claude Code, and log in with your subscription, not an API key. Then create the bot folder and download the fake Telegram setup.

2

Create the bot with BotFather and save the token

On Telegram, message @BotFather, send /newbot, and save the token in a .env file that only you can read. The token is the bot’s password: never put it in git, a screenshot, or a video. The first bot.py only introduces itself to Telegram.

cat > .env <<'EOF'
TELEGRAM_BOT_TOKEN=cole_o_token_aqui
DONOS=
EOF
chmod 600 .env
# terminal 1 (leave it running): the fake Telegram
python3 ferramentas/telegram_falso.py servidor
# terminal 2: the bot, pointed at the fake
TELEGRAM_API=http://127.0.0.1:8081 TELEGRAM_BOT_TOKEN=123:falso python3 bot.py
Expected output 
conectado como @bot_falso_bot

3

The bot listens and replies (echo)

The bot asks Telegram “any new messages?” and waits for up to 50 seconds (long polling). It doesn’t open any ports on the VPS. For now, it just sends back what you wrote.

# terminal 2
TELEGRAM_API=http://127.0.0.1:8081 TELEGRAM_BOT_TOKEN=123:falso python3 bot.py
# terminal 3: you "on your phone"
python3 ferramentas/telegram_falso.py fala --de 111 "oi"
Expected output 
você (111) → oi
bot → Você disse: oi

File for this step: etapas/03-eco/bot.py

4

Only the owner can talk to the bot

Anyone can find your bot. The DONOS list closes the door: an empty list lets nobody in, and the bot displays the number of anyone who tries. That’s how you find your number on the real bot.

TELEGRAM_API=http://127.0.0.1:8081 TELEGRAM_BOT_TOKEN=123:falso DONOS= python3 bot.py
python3 ferramentas/telegram_falso.py fala --de 111 "oi"
# stop the bot and run it with DONOS=111
python3 ferramentas/telegram_falso.py fala --de 111 "/start"
Expected output 
bot → Este bot é privado.          (and in terminal 2: recusado: from.id=111)
bot → Pronto. Peça o que quiser na VPS. Antes de mudar qualquer coisa eu pergunto.

File for this step: etapas/04-donos/bot.py

5

The request goes to Claude Code, in read-only mode

Now the request goes to claude -p, with the safeguards built into the command itself:

  • the AI can only use read tools;
  • keys, SSH, logins, and all writes are denied;
  • anything not allowed is refused without asking;
  • your personal Claude Code settings are ignored;
  • everything runs inside area/.
mkdir -p area/logs && for i in 1 2 3; do seq 1000 > area/logs/app-$i.log; done
TELEGRAM_API=http://127.0.0.1:8081 TELEGRAM_BOT_TOKEN=123:falso DONOS=111 python3 bot.py
python3 ferramentas/telegram_falso.py fala --de 111 "quanto espaço livre tem no disco?"
python3 ferramentas/telegram_falso.py fala --de 111 "apaga a pasta logs"
ls area/logs | wc -l
Expected output 
bot → Sobram 1,3 TB livres de 3,7 TB …          (the numbers reflect your disk)
bot → Não consegui apagar a pasta logs …       (the command was denied)
3

File for this step: etapas/05-leitura/bot.py

6

The AI proposes; the bot checks

The AI now replies in a fixed format: the answer and, if anything needs to change, the exact commands. The bot checks them without AI:

  • only simple commands (rm, mv, cp, mkdir, touch, gzip, gunzip, tar);
  • only options from a short list;
  • no characters that chain or redirect commands;
  • all paths must stay inside the work area.
TELEGRAM_BOT_TOKEN=x python3 -c "
import bot
for p in ['rm -r logs', 'rm -r ~/.ssh', 'rm -r logs; reboot', 'tar -C/tmp -xf a.tar', 'cp --target-directory=/tmp logs', 'rm -rf .']:
    try: bot.validar(p); print('aceito ', p)
    except ValueError as e: print('recusa ', p, '-', e)
"
Expected output 
aceito  rm -r logs
recusa  rm -r ~/.ssh - passos com caractere proibido
recusa  rm -r logs; reboot - passos com caractere proibido
recusa  tar -C/tmp -xf a.tar - opção não permitida: -C/tmp
recusa  cp --target-directory=/tmp logs - opção não permitida: --target-directory=/tmp
recusa  rm -rf . - não posso apagar ou mover a própria área

In the bot, “delete the logs folder” now returns Vou fazer: …, Comandos: rm -r logs, and Confirma? (sim/não), and nothing is deleted yet.

File for this step: etapas/06-proposta-e-validador/bot.py

7

After “sim,” the bot runs the commands

Only sim, s, confirmo, confirma, yes (even in a sentence, like “sim, pode apagar”), or pode, ok, manda, faz on their own confirm. A message with “?” never confirms: “pode listar antes?” won’t delete anything. The request is valid for 10 minutes, and a .tar archive is checked before it’s opened.

python3 ferramentas/telegram_falso.py fala --de 111 "apaga a pasta logs"
python3 ferramentas/telegram_falso.py fala --de 111 "não"
python3 ferramentas/telegram_falso.py fala --de 111 "apaga a pasta logs"
python3 ferramentas/telegram_falso.py fala --de 111 "sim"
ls area
Expected output 
bot → … Confirma? (sim/não)
bot → Cancelado. Nada foi mudado.
bot → … Confirma? (sim/não)
bot → Feito:
      rm -r logs → ok

File for this step: etapas/07-sim-e-execucao/bot.py

FAQ

Frequently asked questions

Things people often ask before getting started.

Do I need to know how to code?

It helps if you can copy and paste commands in a terminal. The code is provided at each step, along with a finished file to check your work. If you get stuck, the README has a ready-made prompt for Claude Code to work through it with you, one step at a time.

Does it cost anything beyond the subscription?

No. The bot uses the Claude Code subscription you already have and only Python’s standard library. Telegram is free. You just need a VPS.

Can the AI delete something without my asking?

No. It only has read tools, is confined to one folder, and never sees keys. To make a change, it only writes a proposal. The bot runs it after your “sim,” and only simple commands inside the work folder.

What if someone else finds my bot?

They get “Este bot é privado.” and their number is logged. Only the numbers on the DONOS list can talk to the bot.

I already have the ready-made kit. Why follow the guide?

To understand it and make changes yourself. When you build it, you know where each safeguard is and why it exists, and you can safely add commands or folders.

Can I run it without a VPS, on my computer?

The tests with fake Telegram run on any Linux system with Python 3 and Claude Code. The real bot is designed to stay running on a VPS.
