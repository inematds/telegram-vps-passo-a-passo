Em resumo

É um passo a passo para você montar, na sua própria VPS, um bot de Telegram que passa os seus pedidos para o Claude Code pela sua assinatura. Serve para quem tem um servidor e quer cuidar dele pelo celular sem dar à IA a chave da casa: só você fala com o bot, a IA só lê, e qualquer mudança espera o seu "sim". São 9 etapas, cada uma com o comando, a saída esperada e um Telegram falso para testar. Você precisa de uma VPS Linux com Python 3, do Claude Code logado na sua assinatura e de uma conta no Telegram.

O ganho

O servidor no bolso, sem entregar a chave

Você não precisa abrir o notebook, entrar por SSH e lembrar comando para saber se o disco está cheio. E também não precisa confiar cegamente numa IA com acesso ao terminal.

Hoje

Notebook, SSH e comando de cabeça

Para ver o espaço do disco ou limpar uns logs, você precisa estar no computador, entrar no servidor e acertar o comando. Ou dá acesso total a uma IA e torce para ela não apagar o que não devia.

Com o bot

Uma pergunta no Telegram

"Quanto espaço livre tem?" volta com os números. "Apaga a pasta logs" volta com o que vai ser feito, os comandos exatos e "Confirma?". Só depois do seu "sim" alguma coisa muda.

Como funciona

Cinco travas, todas no código

Nenhuma trava depende de a IA "obedecer". Cada uma é uma regra que o programa cumpre, mesmo que a IA erre ou seja enganada por um arquivo.

Você no Telegram→Lista de donos→IA só lê→Proposta conferida→Seu "sim"→Bot executa e anota
1

Porta com lista

Só os números de quem está na lista entram. Lista vazia = ninguém entra; o bot só anota quem tentou.

2

Visita sem mexer em nada

A IA pode olhar, mas só dentro de uma pasta de trabalho, e nunca vê chaves, SSH nem logins.

3

Orçamento antes do serviço

Para mudar algo, a IA só escreve o que faria. O bot confere com uma lista curta de comandos permitidos.

4

Você assina embaixo

Só um "sim" claro libera, e vale por 10 minutos. Quem executa é o bot, exatamente o que mostrou.

5

Caderno de registro

Cada pedido, proposta, "sim" e resultado vira uma linha em auditoria.jsonl, sem o token.

⚠️ O furo que o passo a passo fecha

O Claude Code soma as permissões do seu próprio settings.json às do bot. Testamos: numa máquina com rm liberado, o pedido "apague a pasta logs" apagou de verdade, mesmo com o bot pedindo "só leitura". Na etapa 5 o bot passa a ignorar essas configurações (--setting-sources ""), e o teste final coloca uma armadilha dessas de propósito para provar que ela não funciona.

1

Preparar a VPS e o Claude Code

Entre com um usuário comum (não root), instale o Claude Code e faça login com a sua assinatura, não com chave de API. Depois crie a pasta do bot e baixe o Telegram falso.

python3 --version
curl -fsSL https://claude.ai/install.sh | bash
claude                         # /login com a conta da assinatura → /exit
env | grep -c ANTHROPIC_API_KEY
claude -p "responda só: ok" --model haiku
mkdir -p ~/kits/telegram-vps-remoto/ferramentas ~/kits/telegram-vps-remoto/testes
cd ~/kits/telegram-vps-remoto
curl -fsSLo ferramentas/telegram_falso.py https://raw.githubusercontent.com/inematds/telegram-vps-passo-a-passo/main/ferramentas/telegram_falso.py
Saída esperada

0

2

Criar o bot no BotFather e guardar o token

No Telegram, fale com o @BotFather, mande /newbot e guarde o token num .env que só você lê. O token é a senha do bot: nunca vai para git, print ou vídeo. O primeiro bot.py só se apresenta ao Telegram.

cat > .env <<'EOF'
TELEGRAM_BOT_TOKEN=cole_o_token_aqui
DONOS=
EOF
chmod 600 .env
# terminal 1 (deixe rodando): o Telegram falso
python3 ferramentas/telegram_falso.py servidor
# terminal 2: o bot, apontando para o falso
TELEGRAM_API=http://127.0.0.1:8081 TELEGRAM_BOT_TOKEN=123:falso python3 bot.py
Saída esperada 
conectado como @bot_falso_bot

3

O bot ouve e responde (eco)

O bot pergunta ao Telegram "tem mensagem nova?" e espera até 50 segundos (long polling). Não abre nenhuma porta na VPS. Por enquanto ele só devolve o que você escreveu.

# terminal 2
TELEGRAM_API=http://127.0.0.1:8081 TELEGRAM_BOT_TOKEN=123:falso python3 bot.py
# terminal 3: você "no celular"
python3 ferramentas/telegram_falso.py fala --de 111 "oi"
Saída esperada 
você (111) → oi
bot → Você disse: oi

4

Só o dono fala com o bot

Qualquer pessoa pode achar o seu bot. A lista DONOS fecha a porta: lista vazia não deixa ninguém entrar, e o bot mostra o número de quem tentou. É assim que você descobre o seu número no bot de verdade.

TELEGRAM_API=http://127.0.0.1:8081 TELEGRAM_BOT_TOKEN=123:falso DONOS= python3 bot.py
python3 ferramentas/telegram_falso.py fala --de 111 "oi"
# pare o bot e rode com DONOS=111
python3 ferramentas/telegram_falso.py fala --de 111 "/start"
Saída esperada 
bot → Este bot é privado.          (e no terminal 2: recusado: from.id=111)
bot → Pronto. Peça o que quiser na VPS. Antes de mudar qualquer coisa eu pergunto.

Arquivo desta etapa: etapas/04-donos/bot.py

5

O pedido vai para o Claude Code, só para ler

Agora o pedido vai para o claude -p, e as travas estão no próprio comando:

  • a IA só pode usar ferramentas de leitura;
  • chaves, SSH, logins e qualquer escrita ficam negados;
  • o que não foi liberado é recusado sem perguntar;
  • as suas configurações pessoais do Claude Code são ignoradas;
  • tudo roda dentro de area/.
mkdir -p area/logs && for i in 1 2 3; do seq 1000 > area/logs/app-$i.log; done
TELEGRAM_API=http://127.0.0.1:8081 TELEGRAM_BOT_TOKEN=123:falso DONOS=111 python3 bot.py
python3 ferramentas/telegram_falso.py fala --de 111 "quanto espaço livre tem no disco?"
python3 ferramentas/telegram_falso.py fala --de 111 "apaga a pasta logs"
ls area/logs | wc -l
Saída esperada 
bot → Sobram 1,3 TB livres de 3,7 TB …          (os números são os do seu disco)
bot → Não consegui apagar a pasta logs …       (o comando foi negado)

6

A IA só propõe; o bot confere

A IA passa a responder num formato fixo: a resposta e, se precisar mudar algo, os comandos exatos. O bot confere sem IA:

  • só comandos simples (rm, mv, cp, mkdir, touch, gzip, gunzip, tar);
  • só opções de uma lista curta;
  • nenhum caractere que encadeia ou desvia comandos;
  • todo caminho dentro da área.
TELEGRAM_BOT_TOKEN=x python3 -c "
import bot
for p in ['rm -r logs', 'rm -r ~/.ssh', 'rm -r logs; reboot', 'tar -C/tmp -xf a.tar', 'cp --target-directory=/tmp logs', 'rm -rf .']:
    try: bot.validar(p); print('aceito ', p)
    except ValueError as e: print('recusa ', p, '-', e)
"
Saída esperada 
aceito  rm -r logs
recusa  rm -r ~/.ssh - passos com caractere proibido
recusa  rm -r logs; reboot - passos com caractere proibido
recusa  tar -C/tmp -xf a.tar - opção não permitida: -C/tmp
recusa  cp --target-directory=/tmp logs - opção não permitida: --target-directory=/tmp
recusa  rm -rf . - não posso apagar ou mover a própria área

No bot, "apaga a pasta logs" agora volta com Vou fazer: …, Comandos: rm -r logs e Confirma? (sim/não), e nada é apagado ainda.

Arquivo desta etapa: etapas/06-proposta-e-validador/bot.py

7

Depois do "sim", quem executa é o bot

Só confirmam sim, s, confirmo, confirma, yes (mesmo em frase, como "sim, pode apagar") ou pode, ok, manda, faz sozinhos. Mensagem com "?" nunca confirma: "pode listar antes?" não apaga nada. O pedido vale 10 minutos, e um pacote .tar é conferido antes de ser aberto.

python3 ferramentas/telegram_falso.py fala --de 111 "apaga a pasta logs"
python3 ferramentas/telegram_falso.py fala --de 111 "não"
python3 ferramentas/telegram_falso.py fala --de 111 "apaga a pasta logs"
python3 ferramentas/telegram_falso.py fala --de 111 "sim"
ls area
Saída esperada 
bot → … Confirma? (sim/não)
bot → Cancelado. Nada foi mudado.
bot → … Confirma? (sim/não)
bot → Feito:
      rm -r logs → ok

Arquivo desta etapa: etapas/07-sim-e-execucao/bot.py

Testes das travas e o bot ligado de vez

O teste das travas usa uma área temporária e coloca, de propósito, uma configuração que libera rm, para provar que o bot a ignora. Depois o bot vira um serviço do seu usuário e continua no ar mesmo quando você sai do SSH.

python3 testes/testar_travas.py

Dúvidas

Perguntas comuns

O que costuma aparecer antes de começar.

Preciso saber programar?

Ajuda saber copiar e colar no terminal. O código é dado em cada etapa, com o arquivo pronto para conferir. Se travar, o README tem um pedido pronto para o Claude Code montar junto com você, etapa por etapa.

Custa alguma coisa além da assinatura?

Não. O bot usa o Claude Code que você já assina e só a biblioteca padrão do Python. O Telegram é grátis. Você só precisa de uma VPS.

A IA pode apagar algo sem eu pedir?

Não. Ela só tem ferramentas de leitura, presa numa pasta, e nunca vê chaves. Para mudar algo, ela só escreve a proposta. Quem executa é o bot, depois do seu "sim", e só comandos simples dentro da pasta de trabalho.

E se outra pessoa achar o meu bot?

Ela recebe "Este bot é privado." e o número dela fica anotado. Só os números da lista DONOS conversam com o bot.

Já tenho o kit pronto. Para que o passo a passo?

Para entender e poder mudar. Montando você mesmo, você sabe onde cada trava está e por que ela existe, e pode acrescentar comandos ou pastas com segurança.

Funciona sem VPS, no meu computador?

Os testes com o Telegram falso rodam em qualquer Linux com Python 3 e Claude Code. O bot de verdade foi feito para ficar ligado numa VPS.
